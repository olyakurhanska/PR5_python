# Практична робота №5

**Тема:** Ініціалізація та конфігурація веб-проєктів з Django та Flask.

## Мета роботи

Набути практичних навичок створення та конфігурації веб-проєктів на фреймворках Django і Flask: навчитися налаштовувати віртуальне середовище, встановлювати залежності через pip, ініціалізувати проєкти, розуміти їхню файлову структуру, створювати додатки Django, налаштовувати маршрутизацію та запускати сервер розробки.

## Виконані завдання

### 1.1. Віртуальне середовище та pip

Створено й активовано віртуальне середовище `venv`. Встановлено Django 6.1.3 та Flask 3.1.3. Залежності зафіксовано у файлі `requirements.txt`.

Створено скрипт `practical_05_task_1_1.py` для перевірки версії Python і доступності фреймворків.

### 1.2. Відтворення середовища з requirements.txt

Створено друге середовище `venv2` та встановлено залежності з `requirements.txt`. Перевірено збіг версій усіх 11 залежностей.

Скрипт `practical_05_task_1_2.py` отримує інформацію про встановлені пакети у JSON-форматі, генерує файл залежностей, перевіряє версії та обробляє відсутність файлу.

### 2.1. Створення Django-проєкту

Ініціалізовано проєкт `mysite` та додаток `pages`.

Реалізовано URL-маршрути `/`, `/about/` та `/contact/`, включно з обробкою GET-параметра `name`.

Додаток `pages` додано до `INSTALLED_APPS`.

Запуск сервера та доступність сторінок перевірено: запити повертали HTTP 200, а `python manage.py check` не виявив помилок.

### 2.2. Конфігурація settings.py

Налаштовано `LANGUAGE_CODE = 'uk'` і `TIME_ZONE = 'Europe/Kyiv'`.

Створено скрипт `practical_05_task_2_2.py`, який аналізує конфігурацію Django та перевіряє базові параметри безпеки.

Зафіксовано такі результати:

- `DEBUG`: `True`
- `DATABASES`: `django.db.backends.sqlite3`
- `INSTALLED_APPS`: сім додатків, включно з `pages`
- `LANGUAGE_CODE`: `uk`
- `TIME_ZONE`: `Europe/Kyiv`
- Попередження безпеки: 3 (режим налагодження, секретний ключ у файлі, порожній `ALLOWED_HOSTS`)

Ці попередження стосуються використання конфігурації у production і не заважають локальному виконанню практичної роботи.

### 3.1. Flask-проєкт із маршрутизацією

Створено проєкт `myflaskapp` зі структурою `app.py`, `config.py`, `static/`, `templates/` та власним `requirements.txt`.

Використано патерн Application Factory через функцію `create_app()` і конфігурації для розробки та production.

Реалізовано маршрути:

- `/` — головна HTML-сторінка
- `/about` — інформація про проєкт
- `/api/info` — JSON-відповідь із назвою фреймворку, версією, налаштуванням debug та маршрутами
- `/greet` — привітання з GET-параметром `name`
- `/greet/<name>` — привітання з параметром у URL

На скриншотах підтверджено роботу `/api/info` та `/greet/Vika`.

API повернув `framework: Flask`, `version: 3.1.3`, `debug: true` і перелік зареєстрованих маршрутів.

Сервер запускається локально на порту 5000.

### 3.2. Порівняння структури Django та Flask

Створено скрипт `practical_05_task_3_2.py`, який рекурсивно сканує обидва проєкти, ігнорує службові файли та каталоги, будує дерева файлів і виводить порівняльну таблицю.

| Характеристика | Django | Flask |
|---|---:|---:|
| Файли `.py` | 14 | 2 |
| Файли `.html` | 0 | 0 |
| Файли `.css` | 0 | 1 |
| Каталоги | 3 | 2 |
| Загальний розмір (байт) | 7154 | 4413 |

Django має стандартизовану структуру з конфігураційними файлами та окремими додатками. Flask дозволяє організовувати структуру гнучкіше й починати з меншої кількості файлів.

HTML-шаблони в цьому проєкті не створювалися: HTML повертається безпосередньо з обробників маршрутів.

## Встановлення та запуск

У Windows PowerShell перейти до каталогу практичної:

```powershell
cd "C:\Users\Vika\anything2explainer\PR5_Python"
```

Активувати віртуальне середовище:

```powershell
.\venv2\Scripts\Activate.ps1
```

Якщо залежності ще не встановлені:

```powershell
python -m pip install -r requirements.txt
```

Запуск скриптів перевірки:

```powershell
python practical_05_task_1_1.py
python practical_05_task_1_2.py
python practical_05_task_2_2.py
python practical_05_task_3_2.py
```

Запуск Django:

```powershell
cd mysite
python manage.py migrate
python manage.py runserver
```

Перевірити сторінки Django за адресами:

- `http://127.0.0.1:8000/`
- `http://127.0.0.1:8000/about/`
- `http://127.0.0.1:8000/contact/`
- `http://127.0.0.1:8000/contact/?name=Vika`

Запуск Flask в іншій сесії PowerShell після активації середовища:

```powershell
cd "C:\Users\Vika\anything2explainer\PR5_Python\myflaskapp"
python app.py
```

Перевірити адреси:

- `http://127.0.0.1:5000/`
- `http://127.0.0.1:5000/about`
- `http://127.0.0.1:5000/api/info`
- `http://127.0.0.1:5000/greet/Vika`
- `http://127.0.0.1:5000/greet?name=Vika`

Сервери Django та Flask у цій практичній призначені лише для локальної розробки.

## Висновок

Під час практичної роботи створено й налаштовано ізольовані середовища Python, встановлено Django та Flask і перевірено відтворюваність залежностей через `requirements.txt`.

Розроблено Django-проєкт із додатком та маршрутизацією, Flask-проєкт з Application Factory і JSON API, а також скрипти для аналізу конфігурації та структури проєктів.

Установлено, що Django пропонує готову структуру та значну кількість вбудованих компонентів, тоді як Flask забезпечує більшу свободу в організації коду.

Обидва фреймворки придатні для створення вебдодатків Python; вибір залежить від вимог і складності проєкту.
